## How to regenerate

All Rive runs are sequential. The wow sheets and GIFs, about 3.5 minutes:

```
uv run --with pillow --with numpy rive/tools/storyboard_m5.py rive/review/m5/wow
```

Exit code 1 and a `FAIL` line in `wow/gates.txt` when a gate fails. It reuses
`rive/tools/storyboard_m4.py` (sheet, capture, gates, parallax GIF) and `rive/tools/storyboard.py`
(frame and caption layout); both keep their M4 / M1 output (the scene background and the parallax
project are optional parameters that default to the old behaviour).

Other folders:
- head: `uv run --with pillow rive/tools/review_face.py yaw_sweep <M4 avatar.rml>`;
- light: `uv run --with pillow rive/tools/review_face.py light_m5 <older avatar.rml>`;
- newspaper: `uv run --with pillow python rive/tools/motion_review.py --newspaper`;
- scenes: `uv run --with pillow --with numpy rive/tools/review_diorama.py <sceneId> <M4 poster.webp>`
  (campfire with `--same-as=5b10b23`);
- world state: `flutter test test/core/services/world test/features/avatar/presentation/rive`;
- device: see `device/README.md`.

## Not verified

- No real mid-tier device and no battery budget: the device check is an emulator only (ruling 10),
  so the vision's "Wow #1 and #2 in the app on a mid-tier device" stays open.
- No real LLM + TTS app run: both wow sheets use hand-written AU, gaze and lean values (the inhale
  values are what `FacePerformer`'s pre-roll writes at its peak), no audio, and no tool data.
- No macOS UI-lab capture of either wow moment (no computer use): the sheets composite separate
  headless captures of the avatar and the scene, not the app's own stage.
- The newspaper is a tablet-sized folded page in the tablet's draw slot (behind both forearms), not
  a full broadsheet.
- M3's open mouth-construction list is not addressed beyond ruling 1's foreshortening.
- World sync (rain from the weather tool), the window glance, the telescope, hands and Kokoro are
  not in M5 (ruling 13).

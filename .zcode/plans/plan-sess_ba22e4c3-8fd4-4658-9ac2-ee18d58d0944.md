# Global Memory + Prompt Caching (compat-scope)

Two features, one shared design decision: **dynamic content (memory) is injected at the END of the request, never into the system prompt**, so the stable prefix `[system prompt | history]` stays cacheable across turns on every automatic-caching provider (OpenAI ≥1024 tokens, DeepSeek, Gemini implicit, Ollama).

---

## Part 1 — Global memory (fact list + settings UI)

### 1. Model — `lib/core/models/global_memory.dart` (new)
- `GlobalMemoryItem` (freezed): `id` (uuid), `text` (≤200 chars), `updatedAt` (DateTime).
- `GlobalMemory` (freezed): `items` list, capped at 30 items, `maxItemLength`/`maxItems` consts.
- Hand-written `toMap`/`fromMap` with tolerant defaults (precedent: `Chat` in `core/models/chat.dart`).

### 2. Storage
- **`lib/features/chat/data/datasources/global_memory_datasource.dart`** (new): SharedPreferences JSON blob under key `'global_memory'` (pattern: `task_llm_config` blob in `SettingsLocalDatasource` L94-105).
- **`lib/core/repositories/global_memory_repository.dart`** (new interface, `Result<T>`-wrapped): `getMemory()`, `saveMemory(GlobalMemory)`, `deleteItem(id)`, `clearAll()` — interface in core so both chat and settings features can use it without cross-feature imports.
- **`lib/features/chat/data/repositories/global_memory_repository_impl.dart`** (new): try/catch → `StorageFailure` wrapper.
- Memory **enabled toggle** goes through the existing settings chain: `SettingsLocalDatasource` (`_getBoolKey`/`_setBoolKey`, key `'memory_enabled'`, default true) → `SettingsRepository` + impl → `SettingsState.memoryEnabled` → `SettingsCubit.setMemoryEnabled`.

### 3. Extraction — `lib/features/chat/domain/services/global_memory_service.dart` (new)
Mirrors `ChatTitleService` (fire-and-forget, never blocks/disrupts chat):
- `updateMemory(Chat chat)`: guards — feature disabled → skip; already running → skip (in-service flag); parse last exchange (last user body via `getVisiblePrompt()`, last assistant body: extract `message` field from its JSON, fallback to raw). Send **current items + last exchange only** (bounded context).
- Calls new interface method `extractMemory({conversationExcerpt, currentMemory})` on `LlmServiceInterface`.
- Prompt (hardcoded EN, like title gen, `returnJson: true`): "maintain long-term memory about the user; return the complete updated list as JSON `{\"memory\": [...]}`; facts about the user only; merge duplicates; drop contradicted items; ≤30 items, ≤200 chars each; return current list unchanged if nothing new; `[]` if nothing memorable".
- Parse defensively: dedupe (case-insensitive), keep existing item ids for unchanged texts (stable `updatedAt`), cap counts/lengths. **Any failure → log + keep existing memory.**

### 4. Task routing (cost control)
- `LlmTaskType.memoryExtraction` + `TaskLlmConfig.memoryExtractionLlmId` (default null → falls back to current config) → run `build_runner` (freezed/json_serializable).
- `LlmConfigManager._getConfigIdForTask` case + option in `task_llm_config_page`/tile UI, so users can point extraction at a cheap model.
- Stored `task_llm_config` JSON without the new field must keep deserializing (freezed default handles it).

### 5. LLM layer changes
- `LlmServiceInterface.extractMemory(...)` + impl in `LlmService` (non-streaming `promptModel`, `getConfigForTask(LlmTaskType.memoryExtraction)`, own hardcoded system prompt — pattern: `LlmService.generateTitle` L205-247).
- `FakeLlmService.extractMemory`: when demo-active → no-op returning current list (prevents eating scripted demo responses); inactive → delegate to real service.

### 6. Injection (cache-safe) — `chat_streaming_service.dart`
At request assembly (after L145 `messagesForStream = chat.llmMessages`): if enabled and items non-empty, insert **one** `LlmMessage(role: system, body: memoryBlock)` immediately **before the last message** (current user entry), once, before the tool loop. Block format: "Global memory about the user from previous conversations. Use naturally, don't recite.\n- fact…". Never persisted into chat entries. `LlmMessageRole.system` already exists. One-line comment at the injection site stating the placement constraint (cache prefix).

### 7. Trigger — `chat_cubit.dart`
In `onStreamComplete` (next to title gen, L640-644): fire-and-forget `_globalMemoryService.updateMemory(finalChat)`.

### 8. Settings UI
- `memory_page.dart` under `lib/features/settings/screens/memory/`: enable toggle, item list (Dismissible → delete), clear-all with confirm. Items loaded via `SettingsCubit.loadGlobalMemory()` on page init (extraction mutates storage outside the cubit).
- `SettingsCubit` gets `GlobalMemoryRepository` injected; state gains `memoryItems`; methods `loadGlobalMemory`/`deleteMemoryItem`/`clearMemory`.
- Entry section in `settings_screen.dart`.

### 9. DI — `service_locator.dart`
Register `GlobalMemoryDatasource`, `GlobalMemoryRepository`, `GlobalMemoryService` (lazy singletons, chat-feature block); add to `ChatCubit` and `SettingsCubit` factories.

## Part 2 — Prompt caching (compat-scope: stability + observability)

1. **Stability**: guaranteed by Part 1 §6 (late injection). No changes to system prompt assembly — it's already deterministic; username/persona changes are rare and acceptable invalidations. User-message bodies (Date/Avatar Config) stay untouched — needed by the avatar schema and alarm tool.
2. **Observability** — `llm_streaming_service.dart`:
   - Add `'stream_options': {'include_usage': true}` to the stream body.
   - Parse `usage` from the final SSE chunk (OpenAI: `usage.prompt_tokens_details.cached_tokens`; DeepSeek: `usage.prompt_cache_hit_tokens`) and log one line via `AppLogger` ("LLM usage: prompt=X cached=Y (Z%)"). No new `LlmStreamChunk` variant — log at receipt point.
   - Same parse+log for non-streaming `promptModel` responses.
   - Compat watch-point: if a local server rejects `stream_options`, drop the field for localhost baseUrls (verify during testing; Ollama/LM Studio are expected to tolerate or ignore it).

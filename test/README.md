# Test Suite

While iterating, run only the affected tests: `./scripts/ftest.sh
test/features/<f>/` (queued machine-wide, failures-only output). The quality
gate is local — `./scripts/fverify.sh --fix` before finishing any change (dart
fix + format, then format check + analyze + the whole suite, including the
architecture and DI smoke tests). Line coverage for the logic layers:
`./scripts/fcoverage.sh` (see `scripts/README.md`).

## Layout

| Path | What lives there |
|------|------------------|
| `test/core/…` | mirrors `lib/core/…` — models, services, design tokens, DI smoke test |
| `test/features/<name>/…` | mirrors `lib/features/<name>/…` — data / domain / presentation |
| `test/architecture_test.dart` (+ `test/support/`) | the layering gate: analyzer-based checker + scan rules; the checker's own regression fixtures live in the FlutterForge template repository (`tools/checker_tests/`), not here |
| `test/core/di/service_locator_test.dart` | DI smoke test — every registration resolves |
| `test/integration/…` | feature-flow tests: real dependency chains over scripted fakes |
| `test/helpers/` | `golden_test_helper.dart` (fonts + theme wrapper), `rive_test_assets.dart` (`serveFakeRiveAssets()`) |
| `test/**/goldens/` | golden PNGs — see `golden_tests_README.md`; regenerate only on intentional visual change |
| `tool/` | critic/trace harnesses (face–speech, body language, a11y dump) — run with env-var args, not part of `fverify.sh` |
| `integration_test/` | device/emulator tests, several manual-gated (kokoro TTS, wow captures, frame cost) — see `AGENTS.md` |
| `rive/tools/tests/` | the Python suite for the Rive asset pipeline (gated by `./scripts/frive.sh`) |

## Harnesses (reuse before writing a new rig)

The suite's feature-flow tests pump the **real** dependency chain and replace
only the I/O seams with fakes — the opposite of isolated unit tests, on purpose:

- `test/features/home/presentation/widgets/stage/real_reply_rig.dart` — real
  `ChatStreamingService` + `TalkingRepositoryImpl`, mocked LLM/settings I/O
- `test/features/chat/bloc/chat_reply_failure_harness.dart` — the reply path
  driven to failure
- `test/features/home/stage_harness.dart` — the stage assembled with fakes

When you add a cross-layer test, extend a harness instead of rebuilding one.

## Test behavior at boundaries, not plumbing

Each test should fail only when something a user or another layer relies on
breaks. Do not write:

- tests of framework or config (theme brightness, "uses Material 3");
- tests that a widget or provider exists ("renders XView", "provides XCubit") —
  a behavior test already fails if it is missing;
- forwarding tests ("service delegates to repository");
- per-feature copies of shared mechanics. Request ordering and close safety
  come from `LatestRequestWins` (`core/bloc/`), tested in
  `core/bloc/latest_request_wins_test.dart`; failure copy comes from
  `localizeFailure`, tested in `core/l10n/failure_localization_test.dart`.

A feature generated by `./scripts/fgen.sh` starts with one flow test (success;
data source throws `TimeoutException` and a localized network error shows;
retry succeeds) plus a DTO mapping test with `--with-dto`, and its check in the
DI smoke test. Add repository, cubit or screen tests only when real mapping,
rules or interaction logic lands; prefer the one flow test over per-layer tests
for scaffolded/forwarding code. The exception mapper is tested once in
`core/errors/exception_mapper_test.dart`.

## Rules

- **Never wait on the clock**: no `Future.delayed`/`sleep` in tests. Await the
  real future, inject the I/O seam, use `pump(duration)` or `fakeAsync` for
  timers.
- **Never mock pure domain logic**: use the real service and fake only I/O
  seams (data sources, platform channels).
- **No global-state leaks**: full runs (`fverify`, `ftest` without paths)
  group many test files into one shared isolate per shard. A file that passes alone but fails in a full run leaks or depends on global state: fix it, or as a last resort add a `// ftest:isolate` line so it keeps its own isolate. `await getIt.reset()` in tearDown,
  restore `AppLogger`/`debugPrint` overrides, no static mutable state.
- Before optimizing, run `./scripts/ftest.sh --slowest[=N]`; per-file compile
  dominates, so fewer files beat faster tests.

## Fakes and conventions

- `mocktail` (never mockito); `registerFallbackValue` for non-primitives used with `any()`.
- Repository tests assert mapping + typed failures (`isA<StorageFailure>()`), never `Failure.message` strings — see any `*_failure_test.dart`.
- Cubit tests use `bloc_test`; widget tests use fake cubits pushed state via a test-only helper.
- Rive widget tests call `serveFakeRiveAssets()` and `UiKitFile.resetForTest()` in `setUp`.
- New test files mirror the lib path of the class under test.
- `test/flutter_test_config.dart` turns `AppLogger` off during tests.

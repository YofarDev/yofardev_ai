## Review Focus

1. **Player position is unreliable**: it can return null, stall at 0 for a few hundred ms on a
   cold start, or jump backwards (−76 ms seen on the emulator). The mouth must not freeze, jump
   back or run past the audio.
2. **UI-isolate stalls** (300 ms) must not leave the mouth permanently behind; after a stall it
   catches up from the clock.
3. **Odd WAV files**: stereo, 16 kHz / 22.05 kHz / 24 kHz / 44.1 kHz, `LIST` chunks before
   `data`, an odd-length chunk, a truncated `data` chunk, a 0-sample file.
4. **Stop / interrupt mid-sentence**: no mouth event after `stop()`; no leaked timers.
5. **Tier probe on a throttled or busy device** (fps below the gate): it re-probes, never
   promotes a tier from an invalid probe, and never blocks app start.

### Task 1 [zcode]: Pure-Dart WAV amplitude extraction

`audio_analyzer` 0.1.2 ignores `samplesPerSecond` on Android (Amplituda, ~85 ms frames) while
macOS/iOS give 25 ms RMS frames (`round(rms * 100).clamp(0, 100)` on float samples). All TTS
output here is WAV (`tts_datasource.dart` writes `<timestamp>.wav`).

**Files:**
- Create: `lib/core/services/audio/wav_amplitude_extractor.dart`
- Modify: `lib/core/services/audio/audio_amplitude_service.dart`
- Test: `test/core/services/audio/wav_amplitude_extractor_test.dart`,
  `test/core/services/audio/audio_amplitude_service_test.dart`

**Interfaces:**
- Produces `class WavAmplitudeExtractor { const WavAmplitudeExtractor({this.framesPerSecond = 40});
  List<int> extract(Uint8List wavBytes); }`. It throws `FormatException` on an unsupported or
  corrupt file.
- `AudioAmplitudeService.extractAmplitudes(String audioPath)` keeps its signature. For `.wav`
  paths it reads the file and uses the extractor. For anything else, or when the extractor
  throws, it falls back to `AudioAnalyzer`, then to the existing default list.
- Constant `AudioAmplitudeService.frameDuration = Duration(milliseconds: 25)` (40 fps).

**Steps:**
- [ ] Tests first. Build WAV bytes in the test (a helper that writes a RIFF header + PCM16):
  - a 1 s mono 24 kHz full-scale square wave gives 40 frames, each 100;
  - silence gives all 0;
  - a 0.5-amplitude sine gives about 35 (`round(0.5/√2·100)`, ±1);
  - stereo uses channel 0 only (the Swift plugin reads channel 0);
  - a `LIST` chunk before `data`, and an odd-sized chunk (pad byte), are skipped correctly;
  - a truncated `data` chunk uses the bytes present;
  - 0 samples gives an empty list;
  - non-PCM (format ≠ 1) or a missing `fmt `/`data` chunk throws `FormatException`;
  - PCM 8-bit unsigned and 32-bit float (format 3) are supported, with the same scale as PCM16.
- [ ] Window = `max(1, sampleRate ~/ framesPerSecond)` samples. The last window may be partial.
  Value = `round(sqrt(mean(x²)) * 100).clamp(0, 100)`, with x normalised to [-1, 1].
- [ ] Service test: a temp `.wav` file goes through the extractor (the analyzer mock is never
  called). A `.mp3` path, or a corrupt `.wav`, calls the analyzer mock.

### Task 2 [zcode]: Closed-loop lip-sync from the player clock

Replace the open-loop `Timer.periodic` index in `TtsPlaybackService` with a frame index derived
from a playback clock. The M0 drift spike showed the open loop leads by about 250 ms on macOS
and loses whole ticks after every stall.

**Files:**
- Create: `lib/features/talking/domain/services/playback_clock.dart`
- Modify: `lib/features/talking/domain/services/tts_playback_service.dart`,
  `lib/core/services/audio/audio_player_service.dart`,
  `lib/core/di/service_locator.dart` (wiring only),
  `lib/features/chat/presentation/bloc/chat_tts_cubit.dart` only if a call site must change
- Test: `test/features/talking/domain/services/tts_playback_service_clock_test.dart`

**Interfaces:**
- `abstract interface class PlaybackPositionSource { Future<Duration?> currentPosition(); }`,
  implemented by `AudioPlayerService` (the active player's `getCurrentPosition()`, null when no
  player is active).
- `class PlaybackClock`, constructed with `PlaybackPositionSource source`,
  `Stopwatch Function() stopwatchFactory` and `Duration resyncEvery = 100 ms`. Methods:
  `void start()`, `Duration get position` (synchronous estimate), `Future<void> resync()`,
  `void stop()`.
  - The estimate is `anchor + stopwatch.elapsed`, re-anchored on every resync.
  - A resync that returns null, or zero while the estimate is still under 400 ms (cold start),
    keeps the estimate.
  - A backward correction of 120 ms or less is absorbed: the estimate holds still until the
    real position catches up, so the mouth never moves backwards. A larger backward correction
    is a seek, and the clock re-anchors.
  - A forward correction is applied immediately.
- `TtsPlaybackService(TalkingRepository repository, {PlaybackClock? clock, Duration tick =
  const Duration(milliseconds: 16)})`.
  - `startAmplitudeAnimation` keeps its signature and events.
  - Every tick, frame index = `clock.position ~/ frameDuration`, where `frameDuration =
    audioDuration / amplitudes.length` (falling back to 25 ms when the duration is 0).
  - Emit `MouthStateUpdatedEvent` only when the mouth state changes.
  - Emit `AnimationCompletedEvent` once the index reaches the end.
  - Resync every `resyncEvery`.
  - Without a clock (tests, web), use a pure stopwatch clock.

**Steps:**
- [ ] Tests (`fake_async` plus a fake position source and a controllable stopwatch):
  - with a position that tracks time exactly, the mouth states follow the amplitudes in order;
  - after a 300 ms stall (no ticks delivered, then time jumps), the next tick shows the frame
    for the real position: no lost frames, no slow catch-up;
  - a position source that returns null or 0 for the first 300 ms still starts the animation;
  - a −76 ms correction never emits an earlier frame index;
  - a +200 ms correction jumps forward;
  - `stop()` mid-sentence: no events after it, no active timer;
  - `AnimationCompletedEvent` fires exactly once.
- [ ] Keep the existing tests green (`test/features/talking/**`, `caption_cubit_test.dart`).

### Task 4 [zcode]: Quality-tier probe

M0 method ([tiers.md](../spikes/2026-10-m0/tiers.md)): the metric is the P95 of the per-frame
`max(buildDuration, rasterDuration)` from `FrameTiming`. Thresholds: **Ultra ≤ 3.3 ms**,
**High ≤ 6.6 ms**, otherwise Low. The validity gate requires probe fps ≥ 0.9 × refresh,
otherwise re-probe (max 2 attempts). An invalid probe never changes the stored tier.

**Files:**
- Create: `lib/core/services/quality/quality_tier_service.dart`,
  `lib/core/services/quality/frame_timing_source.dart`
- Modify: `lib/core/services/settings_local_datasource.dart` (get/set the stored tier and the
  probe date), `lib/core/di/service_locator.dart`
- Test: `test/core/services/quality/quality_tier_service_test.dart`

**Interfaces:**
- `abstract interface class FrameTimingSource { Stream<List<FrameTiming>> get timings;
  double get refreshRate; }`, with `SchedulerFrameTimingSource` as the production
  implementation (`SchedulerBinding.instance.addTimingsCallback`; removed on dispose).
- Static pure functions on `QualityTierService`:
  - `static double p95Ms(List<double> frameMs)` (nearest-rank);
  - `static QualityTier tierFor(double p95Ms)`;
  - `static bool isValidProbe({required int frames, required Duration window, required double
    refreshRate})`.
- `QualityTierService`, constructed with `FrameTimingSource`, `SettingsLocalDatasource` and
  `Duration probeWindow = 3 s`. It has:
  - `QualityTier get current`, defaulting to `high` before any probe;
  - `Stream<QualityTier> get changes`;
  - `Future<QualityTier> probe()`: collects over the window and returns the stored tier when
    every attempt is invalid;
  - `Future<void> init()`: loads the stored tier, and schedules a probe after the first frames
    when no tier is stored, without awaiting it on startup.
- No UI and no Rive wiring in this task.

**Steps:**
- [ ] Tests:
  - P95 on known lists;
  - the threshold edges (3.3 → ultra, 3.31 → high, 6.6 → high, 6.61 → low);
  - an fps gate failure triggers a re-probe;
  - two invalid probes keep the stored tier;
  - a valid probe persists the tier and emits on `changes`;
  - `init()` with a stored tier does not probe.

### Task 5 [zcode]: `PerformanceDirector` v1

**Files:**
- Create: `lib/features/avatar/domain/services/performance_director.dart`,
  `lib/features/avatar/domain/models/performance_intent.dart` (freezed),
  `lib/features/avatar/domain/services/auto_acting_rules.dart`
- Modify: `lib/features/avatar/domain/services/avatar_cue_service.dart` (delegate gesture
  arbitration to the director), `lib/features/avatar/avatar.dart` (barrel export),
  `lib/core/di/service_locator.dart`
- Test: `test/features/avatar/domain/services/performance_director_test.dart`,
  `auto_acting_rules_test.dart`

**Interfaces:**
- `PerformanceIntent`:
  - `EmotionVector emotion`, `ActionUnits face`, `GazeTarget gaze`, `bool speaking`;
  - `AvatarGesture? pendingGesture`, `int gestureSerial` (it increments on each new gesture so
    a repeat of the same gesture still fires);
  - `String? activeTool`.
- `PerformanceDirector`, constructed with `DateTime Function() now` and `Duration
  gestureCooldown = 1500 ms`. Methods:
  - `void setMood(AvatarMood? mood)`;
  - `void setSpeaking(bool speaking)`;
  - `void setActiveTool(String? toolName)`;
  - `void requestGesture(AvatarGesture g, {GestureSource source})`, with `enum GestureSource
    { llm, auto }`;
  - `void onGestureDone()`;
  - `void onSentence(String text)`;
  - `Stream<PerformanceIntent> get intents` and `PerformanceIntent get current`;
  - `Future<void> dispose()`.
- **Gesture queue:** at most one gesture plays at a time. Requests that arrive while one is
  playing are queued, at most 2 deep; when the queue is full, the oldest `auto` request is
  dropped first. `onGestureDone()` (or a 4 s safety timeout) plays the next request once the
  cooldown since the last start has elapsed. An LLM gesture always outranks an auto gesture.
- **Auto-acting rules** (pure `List<AvatarGesture> gesturesFor(String sentence)`):
  - a sentence ending in `?` gives `think`;
  - a sentence starting with an affirmation (`yes`, `oui`, `exactly`, `exactement`) gives
    `nod`;
  - a negation (`no`, `non`) gives `headshake`;
  - otherwise nothing.

  These are auto requests, so they lose to LLM cues and are rate-limited by the cooldown.
- Gaze: `user` while speaking, `away(0.6)` while a tool is active, `user` otherwise.
- `AvatarCueService` keeps its constructor and behaviour from the outside. Internally it
  forwards gesture cues to `director.requestGesture(..., source: llm)` and triggers the
  animation from the director's `pendingGesture` changes. Its existing tests must stay green.
  Update them only where a timing changes because of the queue, and say so in the report.

**Steps:**
- [ ] Tests:
  - the queue order;
  - LLM outranks auto;
  - the cooldown;
  - the timeout fallback;
  - the serial increments for the same gesture twice;
  - `dispose` closes the stream;
  - each auto rule in English and French;
  - the rules ignore case and leading whitespace.

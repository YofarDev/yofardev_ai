# Moonshot M4 (M4–M6 slice 1): one light, presence, the tablet, the campfire diorama

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans. Each task is tagged `[zcode]` (could go to
> ZCode / GLM: non-Rive, non-UI Dart) or `[claude]` (Rive, art, UI wiring). Work on branch
> `claude/moonshot-m4-dfcd28`, test-first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the first slice of the M4–M6 band: a shared light rig (scene → avatar → UI), presence
(caret gaze, listening lean, backchannel nods, punctuation brows, the idle ladder), tool-call
acting with a tablet prop (Wow #2), the campfire rebuilt as the first diorama with parallax, depth
fog and firelight on the face (Wow #1 complete), the motion-synthesis solvers the new keys need,
and M3's open speech defect (the mumbled jaw).

**Architecture:** unchanged from M3. Dart owns timing (`PerformanceDirector` intents,
`FacePerformer` frames, `HeadMotionSolver`); Rive maps plain view-model values history-free. The
light rig is static data per scene (one table, mirrored in Python and Dart, written once per scene
change); the only per-frame light motion, the firelight flicker, loops inside each Rive file.
Presence signals reach the avatar domain through a core service the composer reports to; the
director turns them into intent fields the performer and the cubit read.

**Tech stack:** Dart 3.8 / flutter_bloc / freezed; Python generators → RML → Rive CLI 1.8.0;
`rive` 0.14.11 / `rive_native` 0.1.11; new packages `sensors_plus` and `battery_plus` (via
`flutter pub add`).

(§4.3 presence, §4.4 dioramas, §4.5 one light, §4.8 motion synthesis, §6 M4–M6 row);

## Rulings (2026-10-29, autonomous; the owner may overturn any of them)

1. **Budget: decimate the baked keys before adding art.** `avatar.riv` is 607,684 B of 614,400.
   14,098 of its records are `KeyFrameDouble`s, and the gestures and presence walks are baked one
   key per frame (`gesture_clap` keys a rotation on all 124 frames). An error-bounded
   Ramer–Douglas–Peucker pass over every linear key run (rotation ≤ 0.002 rad, translation and
   vertex ≤ 0.25 px, scale and opacity ≤ 0.002) runs in the RML emitter, and
   `presence_leaveAndComeBack` becomes walk-out → walk-in chained by exit time instead of a third
   baked copy. Target: ≥ 40 KB headroom with no visible change (gesture frames diff ≤ 1/255 noise
   at the art bible's 360 px phone check). Rejected: a separate prop `.riv` (a second
   `RiveWidget` cannot follow the hand bones or light the face) and lazy-loaded props (the
   runtime has no out-of-band artboards). Fallback if decimation frees < 20 KB: M3 ruling 10
   (formula precision to 2 digits, shared converters).
2. **Contract v7 stays flat**, prefix `light*`. Avatar and scene are separate files, so a nested
   `light` view model could not be shared between them anyway: Dart writes both. Nested VMs and
   the schema-generated contract stay deferred (no consumer needs them yet).
3. **One light table.** `art_bible.SCENES` stays the source; it gains `flicker` (0–1) and
   `key_intensity`/`rim_intensity` already exist. Dart mirrors it in
   `lib/core/design/tokens/scene_lights.dart` (`SceneLights.of(AvatarScene) → LightRig`), kept
   equal by a Python test that parses the Dart file (as the tokens ↔ `AppPalette` test). Every
   scene file also exports its rig as `SceneVM` defaults (for in-scene binds such as the fog);
   `check_contract.py` compares them with `art_bible.SCENES`. The app never reads light back from
   a loaded file: the theme cross-fades on a scene change before the file loads.
4. **Light direction as a vector.** The contract carries `lightKeyX`/`lightKeyY` (−1–1, viewer
   space, toward the light) instead of an angle: Dart computes `cos`/`sin` once, the file's binds
   stay linear. `flickerSeed` is dropped: two files cannot share a clock, and both flickers are
   noise.
5. **Flicker loops in Rive.** The avatar's firelight layer (warm cheek light and the glasses
   glint) runs a looping noise animation blended by `lightFlicker` (a 1D view-model blend, steady
   at 0, full flicker at 1). Dart writes nothing per frame for it. M0's blend bias does not matter
   for noise.
6. **The UI reads the static rig, never the flicker.** `ScenePalette` gains `glassTint` and
   `captionInk`, derived from the scene's `LightRig` (key colour × intensity). A flickering UI
   would distract from reading.
7. **One prop in M4: the tablet**, for every tool that looks something up (`searchGoogle`,
   `getTextContentFromWebsite`, `getCurrentWeather`, `getMostPopularNewsOfTheDay`). The window
   glance, newspaper and telescope variants (vision §4.3) and five-finger hands move to M5–M6;
   the six existing hand poses grip the tablet's edges. Other tools keep M1's glance away.
8. **The tablet is a state, not a gesture.** New `prop` enum (none, tablet) on its own
   state-machine layer after the gesture layer: none has no keys (the gesture layer wins), tablet
   plays a pull-out then a hold loop, back to none plays the put-away. The director suppresses
   gestures while a prop is out. The screen glow on the face is keyed inside the prop animations
   (no Dart). While the tablet is out the head target is (yaw 0.6, pitch −0.5, reading): the
   tablet is held at chest height toward the viewer's right so the 3/4 turn reads and the lit face
   stays visible; the solver's reading saccades are the eyes scanning the screen.
9. **Presence through a core service.** `ComposerActivityService` (`lib/core/services/presence/`)
   takes the composer's reports (typing, caret fraction, last typed character); the home composer
   gets it by constructor from `app_router.dart`. `AvatarCueService` forwards it to the director,
   which turns it into intent fields; `FacePerformer` reads the intent (lean, backchannel nods,
   punctuation brows). No new cubit.
10. **Listening lean is a new number, `lean`** (0–1: the torso and head tip toward the viewer,
    the head lowers a little), sprung by the performer, written in `FaceFrame` like `breath`.
11. **Idle ladder** (`IdleLadder`, avatar domain, injected clock): stage 0 active; stage 1 after
    30 s (glances around every 6–10 s, seeded); stage 2 after 2 min (the tablet comes out for 8 s
    once a minute, "playing with a prop"); stage 3 after 10 min (the tablet stays out, reading).
    Any user activity, speech or tap resets to 0. Battery saver (`battery_plus`) or reduce motion
    freezes the ladder at stage 0. Night dozing and the tap-startle wait for world sync (M7–M9).
12. **Parallax from gyro and pointer.** `ParallaxSource` (`lib/core/services/motion/`): the
    accelerometer's gravity tilt (`sensors_plus`, low-passed, relative to a slowly re-centring
    rest) on phones, the pointer position over the stage on desktop and web; output −1–1,
    clamped, 0 under reduce motion or battery saver. The scene view writes `parallaxX`/`parallaxY`
    at most once per frame with the 0.001 epsilon. All scenes carry the two numbers; only the
    campfire binds them in M4.
13. **Campfire lints clean by construction.** The scene generator passes every non-emissive
    colour through `art_bible.fit_colour(c, scene)` (clamp HSV value into the scene's range and
    saturation under its cap, hue kept); fire, sparks, glow and stars are named `emit*`. The other
    three scenes keep their baseline debt until their rebuilds (M5–M6).
14. **Six planes, three fog veils.** sky → far hills/pines → mid hills → near pines → ground,
    fire, tent → foreground bushes; parallax gain 0, 0.15, 0.3, 0.5, 0.7, 1.0 of 40 px; a fog veil
    (`lightFog` colour, alpha 0.55 / 0.35 / 0.18) sits in front of each of the three back planes.
    Bleed covers the 40 px travel. No feathered depth of field in M4 (tier-gated FX are M5–M6).
15. **Motion solvers only where keys are new.** `rive/tools/motion_synth.py` turns an intent
    (from, to, start, duration) into keys with the art bible's 18 % anticipation, 12 % overshoot,
    220 ms settle and 40 ms part offsets; the tablet pull-out and put-away use it. Existing
    gestures are not re-synthesised in M4.
16. **The mumbled jaw is fixed in the blender.** The jaw is a slow articulator: a consonant span
    other than `pp` (and `ff`'s tuck) keeps at least 0.65 × the jaw of its neighbouring vowels, and
    the jaw never drops below a 0.12 floor inside a voiced phrase. Objective gate on the M3 speech
    traces: median jaw while speaking ≥ 0.22 (M3: 0.09–0.12), every `pp` span still reaches jaw 0
    and press ≥ 0.85.
17. **Review loop (owner, 2026-10-29):** no critic rounds, no score gate. Each visual asset or
    acting change renders its evidence once into `rive/review/m4/` (indexed by its `README.md`),
    gets one cheap self-check for objective defects only (clipping, pops, broken shapes,
    colour-lint failures, budget), fixes them, and adds one line to `rive/CRITIC_ITERATIONS.md`.
18. **Implementers:** as M3 ruling 8, an unattended run cannot give ZCode the owner's screen or
    a fresh login, so Claude subagents (Sonnet) implement the `[zcode]` tasks; Rive tasks run one
    at a time.
19. **Not in M4:** device frame cost and a mid-tier device run (no farm; the phone is
    off-limits), a real LLM + TTS app run (keys and the owner's screen), the other three
    dioramas, world sync, hands, Kokoro.

## Review Focus

1. **A tool that ends while the tablet is still coming out** (tool runs < 400 ms) or a second
   tool starting during the put-away: the prop layer goes straight to the put-away / back to the
   hold from where it is, never a pop (Task 5 transition durations; Task 7 director test: prop
   stays `tablet` across back-to-back tools, gestures stay suppressed until it is put away).
2. **Speech starting while the user is still typing, or while the idle ladder has the tablet
   out:** speech wins: the ladder resets, the prop goes back, gaze returns to the user, the lean
   relaxes (Task 7 tests).
3. **A scene change mid-flicker or mid-tool:** the light writes once, the flicker blend switches
   without a pop, and the theme cross-fades without rebuilding the router (Task 9 widget test on
   the written light values; the existing `AppTheme.forScene` cache test).
4. **No sensors** (desktop, web, a phone without an accelerometer, a sensor stream error):
   parallax falls back to the pointer or 0 and never throws (Task 9 `ParallaxSource` tests).
5. **Typing bursts** (paste of 2,000 characters, a held key, `?!?!`): one backchannel nod per
   ≥ 2.5 s at most, one punctuation reaction per ≥ 1.2 s, no allocation per keystroke beyond the
   report (Task 7 tests).

### Task 2 [claude]: Motion-synthesis solvers and colour fitting (rulings 13, 15)

  str]]`: anticipation (move `rules.anticipation` × travel away from `b` over the first 18 % of

# v4 UI M2 (app side) + M3 Home Stage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the Rive UI kit into Flutter (M2 app side), then rebuild Home as the "Stage": top chips, live captions, a composer state machine with the Rive orb, stop-in-place, a tool chip and reduce-motion (M3).

**Architecture:** UI-kit Rive widgets live in `lib/core/design/rive/` behind a generic view-model binding moved out of the avatar feature; every widget draws a plain-Flutter fallback until `ui_kit.riv` loads (and in tests). Captions, tool activity and speech input are small domain additions surfaced through cubits/services; the composer mode is a pure function of existing state. Home is rebuilt from the M1 lab's "Stage chips" (L1) layout.

**Tech Stack:** Flutter, flutter_bloc (Cubit), freezed, get_it, go_router, rive 0.14.11 / rive_native, speech_to_text 7.3, permission_handler.

**Spec:** `docs/superpowers/specs/2026-10-26-v4-ui-redesign-plan.md` (§3, §4.1, §5, §6, §7 M2/M3). Contract: `rive/CONTRACT.md` § `assets/rive/ui/ui_kit.riv` (commit `6e3457e`).

## Review Focus

1. Speech input when the microphone permission is denied or STT is unavailable (macOS/Linux/web): the mic must hide or show a toast, never crash or spin; permission is asked on first mic tap, never at launch.
2. Interrupt (tap the orb while thinking/speaking) mid-sentence: audio stops, caption clears immediately, orb returns to idle, the next prompt works.
3. Keyboard open on Android with gesture or 3-button nav: composer sits above the keyboard and above the nav bar; nothing overlaps the caption.
4. Scene change mid-reply: accent/glow/orb colors follow the new scene without rebuilding the Rive controllers (colors are VM writes).
5. `ui_kit.riv` missing or corrupt: every UI-kit widget shows its Flutter fallback; no error box in release.

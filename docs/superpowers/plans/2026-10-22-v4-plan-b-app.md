# v4 Plan B: App integration

> **Who runs this:** the app agent, a cheaper model. The Rive assets come from Plan A, run by a
> different agent at the same time.
> **Read first:**
> - `AGENTS.md`
> - the `flutter-architecture` skill (use it alongside `flutter-testing`)
> - [`rive/CONTRACT.md`](../../../rive/CONTRACT.md)
> - the [design](../specs/2026-10-22-rive-v4-design.md), especially §3 Architecture fit

## Goal

Replace the PNG/Lottie avatar with Rive views driven by the app's existing state. Add the new
acting pipeline: the LLM sets a mood and inline gesture/scene cues, and cues fire in time with
TTS. Replace photo backgrounds with 4 Rive scenes, where tapping a prop triggers a local
reaction. Keep the app's architecture rules intact.

## Scope

**Allowed:** `lib/**`, `test/**`, `integration_test/**`, `pubspec.yaml` (only through
`flutter pub add` and `flutter pub remove`), `assets/txt/**`, the l10n ARB files (only through
`./scripts/fstr.sh`), `AGENTS.md`, `README.md`.

**Never touch** `rive/**`, `assets/rive/**` or `scripts/frive.sh`. Those belong to Plan A. If the
contract needs to change, stop and tell the user.

## Rules

- **TDD for pure logic:** the cue parser, the background mapping, the guard and the reaction
  table.
- **Types:** explicit types everywhere, relative imports, freezed v3 (`sealed` or `abstract`).
- **Errors:** return `Result<T>` (`lib/core/models/result.dart`). fpdart is banned.
- **Strings:** every user-facing string goes through `AppLocalizations`, added with
  `./scripts/fstr.sh`.
- **Codegen:** after any model change, run
  `dart run build_runner build --delete-conflicting-outputs`.
- **DI:** register only in `lib/core/di/service_locator.dart`, and update the DI smoke test
  whenever you add a registration.
- **Dependencies:** no cubit may depend on another cubit. Rive types stay in
  `lib/features/avatar/presentation/` only.
- **After every task:** run `dart fix --apply`, `dart format .` and `./scripts/fverify.sh`
  (must be green), then make one commit for that task.

## When you can start each task

- **B1–B7:** start right away. They don't need finished assets.
- **B8:** needs `rive/CHANGELOG.md` to list A1 (avatar) and A6 (scenes).
- **B9:** needs `rive/CHANGELOG.md` to list A7.
- Until then, use whatever `.riv` files are already in `assets/rive/`. Once A0 has landed, that
  includes the spike files.

## Tasks

### B1. Rive runtime and Rive Lab (unblocks the user's spike gate; do this first)

1. Run `flutter pub add rive`, picking the version that loads files made by the Rive CLI. Check
   the current docs. It is likely 0.14+, which uses rive_native.
2. Confirm the app builds and runs on Android and on macOS, Windows and Linux. If any desktop OS
   is not supported, **stop and report it to the user**.
3. Add `assets/rive/` and `assets/rive/scenes/` to the pubspec assets.
4. Create `lib/features/avatar/presentation/rive/avatar_rive_contract.dart`. It holds every
   artboard, state machine, view model, property, enum value and event name from
   `CONTRACT.md` as constants.
5. Add a debug-only route, `/rive-lab`, registered in `core/router/app_router.dart` behind
   `kDebugMode`. The screen:
   - shows `avatar.riv` layered over a chosen scene
   - has a control for every contract property and trigger (dropdowns for enums, a slider for
     `mouth`, buttons for triggers)
   - shows a live log of the Rive events it receives
   - has an FPS readout (the perf overlay toggle is fine)
6. Strings on this screen may stay hardcoded, because it is debug-only. Add a
   `// ignore-l10n: debug` comment so `fl10n.sh` findings are expected.

### B2. Shared models in `lib/core/models/`

- Add these enums, with names exactly as in the contract: `AvatarMood`, `AvatarGesture`, and
  `AvatarScene` (livingRoom, campfire, beach, deepSpace).
- Add `SceneEvent`: an enum of every scene's `eventId` value, plus a mapping from each
  `AvatarScene` to its allowed events.
- Add `AvatarCue` as a freezed sealed class: `AvatarCue.gesture(AvatarGesture)` |
  `AvatarCue.sceneEvent(SceneEvent)`.
- Add unit tests checking that the enum value names equal the contract strings in
  `avatar_rive_contract.dart`.

### B3. Cue parser (chat domain, pure Dart, TDD)

- Create `lib/features/chat/domain/services/cue_parser.dart`.
- **Syntax:** `[g:<gesture>]` and `[s:<sceneEvent>]`.
- **Stateful across stream chunks:** a cue split across two chunks (for example `[g:la` then
  `ugh]`) must still parse. Text that only looks like a cue (`[note]`) passes through untouched.
- **Output:** the clean text, plus the cues tied to the sentence chunk they appeared in. Cues are
  removed from both the displayed text and the spoken text.
- **Unknown cue names:** drop them and log through `AppLogger`.
- **Scene events:** an event that isn't valid for the current scene is dropped.
- **Wiring:**
  - Hook the parser into the sentence chunking in
    `lib/features/chat/domain/services/chat_streaming_service.dart`.
  - Add a `List<AvatarCue> cues` field (default empty) to `TtsQueueItem` in
    `lib/features/sound/domain/tts_queue_item.dart`.
  - Make sure stored chat entries keep only the clean text.

### B4. Cue timing

- `TtsPlaybackService` (`lib/features/talking/domain/services/tts_playback_service.dart`) emits a
  new `CuesReachedEvent(List<AvatarCue>)` the moment a queue item's audio starts.
- Add a new `AvatarCueService` in `lib/features/avatar/domain/services/`:
  - It subscribes to playback events and forwards cues to `AvatarAnimationService.trigger(...)`.
  - It applies the anti-spam guard: at most 1 gesture per chunk, and a 1.5 s cooldown between
    gestures. Scene events are not throttled.
  - When TTS is disabled, cues fire as soon as their sentence chunk finishes streaming.
- Register it as an eagerly created singleton in `service_locator.dart`. It must own and cancel
  its subscription when disposed.
- Unit-test the guard with a fake clock.

### B5. Mood and prompts

- **Reply JSON:** add a `mood` field. Validate it against `AvatarMood`, fall back to `neutral`,
  and apply it when the reply starts. The mood stays until the next reply sets one.
- **`AvatarAnimation` union**
  (`lib/features/avatar/domain/models/avatar_animation.dart`): add the variants `mood`,
  `gesture`, `sceneEvent` and `presence`.
- **Prompts:** update `assets/txt/system_prompt_*.txt` and the persona files that need it:
  - add the placeholders `$moodList`, `$gestureList` and `$sceneEventList`
  - add the cue syntax, with an instruction to use cues sparingly (at most one or two per reply)
  - inject the values in `lib/core/services/prompt_datasource.dart`, the same way
    `$soundEffectsList` is injected today
- Add tests for mood parsing and the fallback.

### B6. Scenes replace backgrounds

1. In `lib/core/models/avatar_config.dart`, replace `AvatarBackgrounds` with `AvatarScene`. The
   default is `livingRoom`.
2. **Old names map to a scene when read.** Do this in both places: `Chat.avatar` JSON and
   `ChatEntry.getAvatarConfig()` for each reply. Never rewrite stored data.

   | Old background values | Scene |
   |---|---|
   | bedroom, library, classroom, office, mall, restaurant, parisianCafe, hallMansion, artGallery, cinema, livingRoom, christmasLivingRoom | livingRoom |
   | lake, forest, park, sakuraTrees, japaneseGarden, snowyMountain, campfire | campfire |
   | beach, tropicalIsland, swimmingPool | beach |
   | deepSpace, cityscrape, balconyViewOfCityByNight, street, facadeMansion | deepSpace |
   | anything unknown | livingRoom |

   Add a unit test for every old value.
3. `$backgroundList` in the prompt now lists the scene ids.
4. **`change_avatar` tool** (`lib/core/services/agent/avatar_tool.dart`): build every option list
   from the Dart enums (scene, hat, top, glasses, costume). This fixes today's made-up options.
   Add a test asserting the tool schema matches the enums.
5. **Settings:** the background picker becomes a scene picker. Add localized scene names with
   `fstr.sh`.

### B7. AvatarCubit state

- **State:** add `mood`, `scene`, `gestureEvent` (gesture plus an increasing `seq`),
  `sceneEvent` (event plus `seq`), and `presence`. The flat `copyWith` state idiom fits here.
- **New methods:** `onPropTapped(AvatarScene scene, String propId)` and
  `onAvatarTapped(String zone)`.
- **New `PropReactionService`** in the avatar domain: a mapping table from every contract
  `propId` and avatar zone to a reaction (a mood, a gesture and/or a sound effect). Play sounds
  through the sound feature's barrel.
- **bloc_test cases:**
  - a cue arriving sets `gestureEvent` with an incremented `seq`
  - the same gesture twice gives two distinct `seq` values
  - a prop tap applies its reaction
  - a mood event updates `mood`

### B8. Rive views (only after A1 and A6 appear in `rive/CHANGELOG.md`)

- Create `RiveAvatarView` and `RiveSceneView` in
  `lib/features/avatar/presentation/widgets/rive/`.
  - **State to Rive:** bind `AvatarCubit` state to the view-model properties. `MouthState`
    (talking) feeds `mouth`, and `TalkingPhase` feeds `phase`.
  - **Triggers:** fire them from `BlocListener`s with `listenWhen` on `seq`. Combine several
    listeners with `MultiBlocListener`.
  - **Rive events to the cubit:** forward `prop_tapped` and `avatar_tapped` to the cubit.
- Put both views behind the dev-only constant `AppConstants.useRiveAvatar` on the home screen.
  The old widgets stay until B9.
- **Lifecycle:**
  - pause Rive when the app goes to the background, using the existing `AppLifecycleService`
  - load the scene file only when its scene is active, and dispose the old one when switching
- Add `integration_test/rive_contract_test.dart`. It runs on macOS, loads each `.riv` file and
  asserts every name in `avatar_rive_contract.dart` exists.

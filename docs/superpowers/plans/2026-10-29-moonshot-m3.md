**Goal:** close M2's structural face and speech critiques (occluding lids, a 3/4 outline, per-side

with an IK constraint. Text drives phoneme labels; audio drives their timing.

**Tech stack:** Dart 3.8 / flutter_bloc / freezed; Python generators → RML → Rive CLI 1.8.0;
`rive` 0.14.11 / `rive_native` 0.1.11.

## Rulings (2026-10-29, autonomous; the owner may overturn any of them)

1. **Contract v6 stays flat.** Per-side control comes as 14 signed offset numbers,
   `au<Name>L` / `au<Name>R` for 7 AUs (brow inner up, brow outer up, brow lower, lid tighten,
   cheek raise, lip corner pull, lip corner depress), range −1–1, **added** to the symmetric AU on
   that side and clamped to 0–1 by the file. `L`/`R` are the **viewer's** left and right, like
   `yaw` and `roll`. Every v5 consumer keeps working (offsets default 0). The mouth-shape AUs
   (jaw, pucker, stretch, press) stay symmetric: speech is symmetric, and a one-sided smile is
   the corner offsets. Nested view models stay deferred to M4 (M2 ruling 1): nothing in M3 shares
   a VM across artboards, and flat binding is the proven path on `rive_native` 0.1.11.
2. **Kokoro stays deferred.** The rounded-vowel errors are labelling errors, not timing errors:
   text-informed alignment on today's TTS audio fixes them with no native dependency, while the
   ONNX route (onnxruntime + our own G2P, 5–8 days, device verification) adds a package and a
   model download. The `SpeechTimeline` seam is unchanged, so Kokoro still plugs in later.
   Revisit at M4 if speech stays below 9.0 for timing reasons.
3. **Phonemes come from rules, not a dictionary package.** A pure-Dart rule-based grapheme →
   phoneme pass for English and French (the app's two languages) plus a small exception lexicon
   for common irregular words. No new packages, no espeak.
4. **Hands move to M4–M6.** Five-finger hands with ~12 generated poses belong with the tablet prop
   and tool-call acting (Wow #2, M4–M6). M0 estimated head + torso + hands at ≈ 773 KiB, over the
   600 KB budget, and M3's critic gate is face and speech. The six existing hand poses stay and
   ride the new forearm bone.
5. **The M3 skeleton is the arms.** Shoulder, upper-arm and forearm bones per side, sleeves
   skinned across the elbow, and a Rive `IKConstraint` (parentBoneCount 1) toward a `HandTarget`
   node. Gestures key the target (and the elbow-bend direction), not two rotations; the Python
   two-bone solver stays as the authoring check that the runtime pose matches. Torso, legs and
   the presence walk stay keyed (no M3 need).
6. **No `stage` feature in M3.** The avatar feature still has one reason to change (the
   character's performance). There is no camera or composition code yet; the camera director is
   M7–M9. Create `stage` with the `CameraDirector` in M7 if the avatar feature then carries both.
7. **Blinks are a lid sweep.** The upper-lid bones travel down to the lower-lid line; the blink
   animations key one `BlinkDrive` node that the lid binds read as a token, so blinks compose
   with the lid AUs and stay history-free.
8. **Implementers (execution):** as M2 ruling 11, an unattended run cannot give ZCode the owner's
   screen or a fresh login, so Claude subagents implement the `[zcode]` tasks and Claude reviews
   and commits. The tags record which tasks could go to ZCode.
9. **Critic gate:** M2 ruling 12 (fresh independent opus critic per round, face ≥ 9.0 and
   speech ≥ 9.0, at most 6 rounds). Evidence adds a per-side AU sheet, an f/v–s–th–pp sheet at
   phone size (360 px wide), a blink strip, a yaw sheet with the silhouette outlined, and strips
   from the text-aligned timelines.
10. **Budget order:** if `avatar.riv` passes 614,400 B, first delete the overlays the lid rig
    retires (droop, squint, squint line), then share converters across binds, then drop formula
    literal precision to 2 digits on sub-pixel terms.
11. **Not in M3:** device frame-cost measurement (no device farm; the phone is off-limits), a real
    LLM + TTS app run (needs keys and the owner's screen), the schema-generated contract (moves to
    M4 with the nested VMs, which reshape it anyway).

## Review Focus

1. **A one-sided offset at the clamp edges:** `auBrowLower = 1` with `auBrowLowerL = 1` and
   `auBrowLowerR = −1` gives a full left lower and a neutral right brow; no bone travels past its
   1.0 pose (Task 5 history-free/clamp test).
2. **Text that does not match the audio** (a caption with emoji, numbers, markdown, another
   language, or empty text): the analyzer never throws and falls back to the audio classifier
   when the alignment cost is too high (Task 3 tests).
3. **A blink fired during a happy squint or a sad droop:** the lid closes fully and reopens to the
   AU pose, with no lash stroke crossing the glasses or the iris showing through (Task 4 render
   check).
4. **Yaw ±1 combined with every mood and the f/v shape:** the mouth stays inside the face outline
   and the far lens stays inside the silhouette (Task 6 sheet check).
5. **A gesture interrupted by another gesture or by `presence`:** the IK target blends from where
   it is; the elbow never flips direction mid-move (Task 7 motion check).

**Files:**

  exact `say` commands; 16 kHz mono, each ≤ 120 KB)

**Produces:**
- `class PhonemeToken { final Viseme viseme; final bool vowel; final int word; final bool
  wordEnd; }` and `class TextPhonemizer { const TextPhonemizer(); List<PhonemeToken>
  phonemize(String text, {String language = 'en'}); }`. Strips markdown, emoji, URLs; spells out
  digits per language; rule-based graphemes (digraphs first: th, sh, ch, ph, wh, ng, qu, oo, ou,
  ow, ee, ea, ai, ay, oa, oi, eau, au, ou, on, an, en, in…) plus an exception lexicon of the ~150
  most common irregular words per language (it must include *blue, you, do, who, two, to, too,
  through, so, go, no, know, oh, view, new, one, was, would, could, should, of, are, here, there,
  their, eye, I*). Unknown script → empty list.
- `class PhonemeAligner { const PhonemeAligner(); AlignedVisemes? align(List<PhonemeToken>
  tokens, SpeechFrames frames); }` with `AlignedVisemes { List<VisemeSpan> spans; double
  costPerFrame; }`: a monotonic Viterbi over 25 ms frames where each token emits a score from the
  frame's features (voicing, band shares, ZCR, energy: the existing classifier's features turned
  into per-class scores), silences may be inserted at word ends, and each token has a minimum of
  1 frame (2 for vowels) and an expected-duration prior (vowel 90 ms, fricative 80 ms, others
  60 ms). Returns null when tokens are empty.
- `SpeechAnalyzer.analyze(WavPcm pcm, {String? text, String language = 'en'})`: computes frames
  once (`SpeechFrames`, exposed for the aligner), aligns when the phonemizer yields tokens and
  uses the aligned spans when `costPerFrame ≤ maxAlignCost` (constant, tuned on the fixtures),
  else today's classifier spans; prosody marks are unchanged. `pp` spans keep the ≥ 50 ms rule.
- `AudioAmplitudeService.analyzeSpeech(path, {String? text, String language = 'en'})`;
  `TtsQueueService.peekLanguage(String audioPath) → String?`; the cubit passes both.

- [ ] Tests: phonemizer: "blue" → [pp, rr?, ou] with the last viseme `ou`; "so" ends `oh`; "view"
  contains `ff` then `ou`; "Bonjour" (fr) contains `pp` and `ou`; "😀 **hi** 42" (en) phonemizes
  "hi forty two"; "" and "日本" → empty. Aligner on synthetic frames: a token list [ss, oh] over 8
  noise frames then 12 dark-tone frames puts the boundary within ±1 frame. Analyzer on each
  fixture (`blue_sky.wav` "The sky is blue.", `so_true.wav` "So true, you know.",
  `fine_view.wav` "A fine view of five vines."): rounded words' vowel spans are `ou`/`oh`/`rr`
  (no `ih`/`aa`), every f/v has an `ff` span, every p/b/m has a `pp` span ≥ 50 ms; mismatched
  text ("Completely different words here." on `blue_sky.wav`) falls back (returns the classifier
  spans) without throwing; a 6 s fixture still analyses in < 150 ms.
